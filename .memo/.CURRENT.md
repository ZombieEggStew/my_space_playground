## 2. 目标架构

### 2.1 核心原则:模块 = 能力 + 该能力 UI 的所有者

> **装模块 → 获得能力(含其 HUD);卸模块 → 能力连同 UI 一起消失,无泄漏、无残留。**

- `HUDManager` 只做**底层渲染 API**:决定元素挂 static/far/group 哪一层、统一特效合成、清除。
- `module_hud` 是船级 **HUD 门面模块**(决策 #19):集中管理所有模块的 HUD 注册、转发包装给 HUDManager;**不做 2D 投影与悬停检测**(投影原语在 camera,悬停检测在 aim,见 #18/#21)。可被打坏。
- 能力模块负责自己能力的 UI **组装与生命周期**:逻辑与呈现拆开,呈现层内置 `<name>_view`(而非全局外置)。
- 跨模块**状态**走通信层(§2.2);模块内部(模块 ↔ 自身 `<name>_view`)走场景内类型化引用。

**判别规则(节点归属依据)**:
- **玩家固有属性**(不依附任何玩法模块就存在):血量、速度、buff 状态 → `module_hud` 的可换子插件 `player_stats_view` 显示,Stat 绑定。
- **模块能力相关**(只有装了模块才存在):目标(radar)、能量(booster)、热量(laser)、护盾(shield)、
  瞄准/预测准星(aim,已吸收 predict)→ **各模块自持的 `<name>_view`**。
- 数值面板(Stat 驱动)→ 可集中 `player_stats_view`;动态元件(每帧位置/几何由玩法驱动)→ 留在玩法模块的 `_view`。

### 2.2 三级通信模型

| 级别 | 载体 | 管什么 | 判定规则 |
|---|---|---|---|
| ① 模块内私有 | 模块场景内 `@export`/`@onready` 类型化绑定 | 模块 ↔ **它自己的** `<name>_view` / 私有子组件 | 收发双方在同一模块内(一起装卸);禁止 `get_node("../../")` 相对路径 |
| ② 飞船级 | `ShipBus`(船上节点,`class_name ShipBus`) | 同船兄弟模块间的输入/状态(含 hover) | 收发双方是同一艘船的兄弟模块 |
| ③ 世界级 | 全局 `SignalBus`(autoload) | 目标 spawn/died、伤害、玩家注册等"世界实体"事件 | 不依附任何一艘船的事件 |

纪律(两级总线通用):**只声明信号,零逻辑零状态**;"当前值"存模块/Stat,bus 只发"变化"脉冲。

**SignalBus 信号归类(定稿)**:

| 信号 | 归到 |
|---|---|
| `on_player_registered` / `on_lockable_target_spawned` / `on_lockable_target_died` / `on_damage_dealt` | ③ 世界级 |
| `on_player_try_lock` / `on_player_boost` / `on_toggle_engine` / `on_toggle_track_mouse` / `on_player_look_backward` / `on_player_look_around` / `on_player_try_use_item_1` / `on_player_lock_target` | ② 飞船级 ShipBus |
| `on_target_hovered` / `on_target_unhovered` | ② 飞船级 ShipBus(检测点 = `aim`(selection),载荷只带 `target` 身份;aim 本地状态直接驱动 aim_view,radar_view 订阅做高亮,见决策 #27) |

> 无「① 删除」类信号:① 是**引用方式**(场景内绑定),不是总线。hover 检测点落在 `aim`(selection),它从 radar_view 快照拿 `screen_rect` 做命中测试(几何走 getter 拉取,不占总线;见决策 #27);检测结果(仅身份)经 ② 发布,`radar_view` 订阅做高亮。

### 2.3 命名约定与目录结构(v2,替代原 `xxx_compat`)

**命名(三种角色)**:

| 角色 | 文件/类名 | 示例 |
|---|---|---|
| 能力逻辑(身体) | `module_<name>.gd` → `<Name>Module` | `module_radar.gd` → `RadarModule` |
| 呈现/视图(该能力的 UI+3D 视觉) | `<name>_view.gd` → `<Name>View` | `radar_view.gd` → `RadarView` |
| 大脑/决策 | `control_module.gd` / `ai_module.gd` | `ControlModule` / `AIModule` |
| 容器/总线/门面 | 无 `module_` 前缀 | `modules_manager` / `ship_bus`;特例 `module_hud` = 门面模块 |

**目录(按能力分文件夹,已初步整理)**:

```
scripts/module/
├─ base/                # 基类:module / module_3d / module_engine / module_weapon / module_ui / module_component
├─ core/                # 容器与总线:modules_manager.gd / ship_bus.gd
└─ modules/
   ├─ module_hud.gd      # 门面模块(内嵌可换子插件 player_stats_view)
   ├─ move/    module_move_controller.gd
   ├─ camera/  module_third_camera.gd
   ├─ booster/ module_booster.gd
   ├─ laser/   module_laser_gun.gd + heat_manager.gd + laser_gun_hud_system.gd
   ├─ aim/     module_aim_mechanics.gd + module_target_selection.gd + aim_view.gd
   ├─ radar/   module_radar.gd + radar_view.gd
   ├─ shield/  module_shield.gd
   └─ brain/   control_module.gd / ai_module.gd
```

> `scenes/modules/<name>/…` 与之一一镜像;`_view` 通常作为模块场景内的子节点/子场景,随模块一起装卸。
> 文件搬迁牵动 `.tscn` 的 `ext_resource path` 与 `.uid`,必须同步改 + `--headless --import` 刷新(见 §7)。

### 2.4 模块系统:身体/能力 与 大脑/决策 分离(2026-09-07 定案)

**动机**:现状"同一艘船怎么动/怎么打"有两套并行系统——玩家侧模块直接读 `Input`
(`module_move_controller` 读按键/鼠标,booster 听 `on_player_boost_input`);敌人侧
`AIBrain`+`MoveSM`(自实现移动)+`CombatSM`/`state_attack`(自 spawn 子弹,目标硬编码玩家)。
重构为:一份共享实现 + 两种大脑。

```
玩家输入(键鼠/手柄) ─┐
                      ├─→ 归一化命令 → 共享模块(engine/booster/weapon/radar…)
敌人 AI 决策        ─┘   set_throttle(0..1) / set_steer(Vector2) /
                         set_boosting(bool) / set_firing(bool) / set_aim_dir(Vector3)
```

**命令接口原则**:模块只懂命令、不懂意图(前进键与 AI 追击在模块看来都是 `set_throttle(1.0)`)。
载体(决策 #12):连续量=直接方法,离散事件=ShipBus 信号;大脑对未装模块空指针降级。

**模块分类**:

## 4. 设计定案与待定项

### 4.1 雷达机制 ✅ 已定(2026-09-07)

- **定位**:敌我飞船**直接复用**的模块;装了就决定该船**视野范围**(半径 R 球形),提供视野内所有可侦测目标。
- **信息源**:③世界级 `on_lockable_target_spawned/died` 事件(增量)+ **"detectable" 组快照**
  (`AbleToBeLocked` 进组;radar 用 `get_tree().get_nodes_in_group("detectable")` 拉全量,支持中途装卸/重装同步)。
- **半径过滤**:radar 内部按 `root.global_position.distance_to(target) <= detection_radius` 过滤
  (`@export detection_radius`,敌我同一套逻辑);维护"视野内"集合,进出视野各发一次事件。
- **过滤频率**:事件驱动 + 每帧距离检查;实现从简(快速迭代,随时可改)。
- **发布契约**:只发布**身份 + 生命周期** — `on_target_entered(target)` / `on_target_exited(target)` +
  `get_targets_in_range()`;具体状态(3D 坐标/血量/速度)消费方**从目标节点直接读**;
  **2D 投影由各 _view 自理**:radar/aim 身体不算 2D;玩家侧 `radar_view` 投影当前目标位(选框/血条),`aim_view` 投影自身预测点(lead/lock),各自用 camera 原语;
  阵营过滤由消费方做(radar 给全量 + 各目标 `team_id`)。
- **目标几何数据契约(两通道,见 #23)**:radar/aim 身体只算 3D;radar_view 投影当前目标位(选框/血条),aim_view 投影自身预测点(lead/lock),各自用 camera 原语;仅 hover 命中所需的 `screen_rect` 由 radar_view 投影后缓存,aim(selection)getter 拉取;离散事件(进/出探测、hover、锁定)才走总线,载荷只带 `target`。
- **hover 数据流定稿(决策 #27)**:radar_view 每帧集中投影缓存 `_rect_cache: {target: Rect2}`(单一数据源:同时喂 selector 显示与 aim 判定;selector 变纯显示、`mouse_filter=IGNORE`,不再发鼠标信号);aim(selection)每帧取 `get_viewport().get_mouse_position()` 遍历 rects 自判,状态变化才 emit `on_target_hovered/unhovered` 走 ② ShipBus,载荷只带 `target` 身份;aim 经 `ModulesManager.get_radar_view()` 类型化 getter 拉取,取不到 → 禁 selection 降级;目标离屏(rect 清空)/死亡/radar 卸载 → aim 自动 unhover。
- **对称性前提**:玩家飞船也要挂 `AbleToBeLocked`,否则敌人雷达侦测不到玩家(顺带解锁"玩家被锁定"玩法)。
- **"可侦测"规则扩展**:放 `AbleToBeLocked` 组件(组件自报是否可侦测),radar 只管半径。
