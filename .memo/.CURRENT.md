## 2. 已修复并验证

### 2.1 Bug 1 — 多个特效互相抢占 `position`

**现象/原因**:`UIFlowEffect`(视差)、`UIBoostOffsetEffect`(加速扩散)、`UIBoostShakeEffect`(加速抖动)
直接写**同一组控件**的 `position`,互相拉扯且覆盖作者摆好的布局;其中 `UIBoostShakeEffect` 还是
`position += random` 的**随机游走**,加速时会越抖越偏。

**修复方案**:特效不再直接写 `position`,各自只写 `meta` 里的独立 offset 通道,
由 `HUDManager` 每帧统一合成 `position = 基准位置 + flow + shake`。

| 文件 | 改动 |
|---|---|
| `scripts/Manager/HUD_manager.gd` | 新增 `_dynamic_groups` 追踪;`register_hud_group` 时捕获 `hud_base_pos` 并初始化 offset 通道;`_process` 统一合成 |
| `scripts/ui/ui_float_effect.gd` | 视差只写 `hud_flow_offset` 通道;改用 Dictionary + `is_instance_valid` 防护 |
| `scripts/ui/ui_boost_shake_effect.gd` | 抖动只写 `hud_shake_offset` 通道;随机游走改为平滑 lerp;加 `is_instance_valid` 防护 |

**验证**:静止时面板停在作者摆好的位置;移动鼠标面板跟随视差;加速时扩散+围绕原位抖动;
松手后平滑回基准位置。

### 2.2 Bug 2 — 远 HUD 坐标系错位

**现象/原因**:`hud_far_manager` 每帧把自己 `position` 设为机头投影 `nose_pos_2d`(整个图层跟随机头),
而 `crosshair_3` 却用**视口全局坐标**(`mouse_pos`/`nose_pos_2d`)设自己的**局部** position,
实际渲染在 `机头 + 鼠标` 处(双重偏移,几乎必偏出屏幕)。`dead_zone_indicator`/热量条是刻意设计成
"机头局部坐标",本身正常。

**修复方案**:保留"远 HUD 图层跟随机头"的现有设计,只修正 `crosshair_3` 的坐标换算,
并把瞄准消费方同步换算回视口坐标。

| 文件 | 改动 |
|---|---|
| `scripts/hud/crosshair_3.gd` | `set_target_pos` / `reset` 改为 `position = 视口坐标 - hud.position`(转机头局部) |
| `scripts/modules/module_component/laser_gun_hud_system.gd` | `get_aim_point_screen_pos()` 返回 `position + hud.position`(转回视口坐标,保证瞄准不坏) |
| `scripts/modules/module_laser_gun.gd` | 死代码 `_get_crosshair3_screen_pos()` 顺带同步换算,防以后被启用时踩坑 |

**验证**:绿色十字准星跟随鼠标、被死区圈限制在边缘;开火子弹朝准星方向飞;死区圈/热量条照旧跟随
机头投影;机头转出屏幕时准星隐藏。

### 2.4 Bug 3 — 特效硬耦合父节点读 boost 状态

**现象/原因**:`ui_boost_offset_effect.gd` / `ui_boost_shake_effect.gd` 通过 `get_parent().is_boosting`
读加速状态,一旦特效节点被重挂载就静默失效;`EffectManager` 整个类只为缓存这一个 bool 而存在。

**修复方案**:两个特效改为 `_ready()` 里直接 `SignalBus.on_player_boost.connect(_on_player_boost)`
自存 `_is_boosting`;删除 `EffectManager`(文件 + 场景引用一并移除)。

| 文件 | 改动 |
|---|---|
| `scripts/ui/ui_boost_offset_effect.gd` | 自存 `_is_boosting` 并监听 SignalBus;`if _is_boosting:` 替换 `get_parent().is_boosting` |
| `scripts/ui/ui_boost_shake_effect.gd` | 同上;删除 `"is_boosting" in get_parent()` 鸭子类型读取 |
| `scripts/Manager/effect_manager.gd` | 已删除;`scenes/game_scene.tscn` 移除其 ext_resource 与节点脚本引用(`EffectManager` 保留为纯分组 Node) |

**验证**:按 Shift 加速扩散/抖动效果与之前一致;游戏启动无报错。

### 3.1 Bug 4 — 目标 UI 泄漏风险 🔴

- `module_player_aim` 给每个可锁定目标 spawn `crosshair_1` + `hp_bar_target`,
  靠 `_process` 里 `is_instance_valid(_target)` 自毁。
- 但**离屏时 `set_process(false)`**——目标在离屏时死亡,`_process` 不再运行,节点永不 `queue_free`,泄漏。
- 另注意:`module_player_aim.locked_target` / `hovered_target` 在目标死亡后可能悬挂,
  `handle_locked_target()` 无 `is_instance_valid` 防护,有崩溃风险(修生命周期时一并处理)。

**方案**:连 `target.tree_exited` / `on_death` 信号自毁,而不是在 `_process` 里轮询。

## 4. 结构性问题(重构动机)

### 4.1 注册 API 是四套并行,契约不一致
`HUDManager` 的 `register_hud_group(Control)→MyHUD` / `register_hud_static(PackedScene)→裸Node` /
`register_hud_far(scene|node)` 返回类型各不相同;调用方风格也乱(module 链式 / manual setup /
far / far_node 四种写法)。同一个"把 UI 挂到 HUD"的意图,四套写法。

### 4.2 特效是"全局单例"持有控件数组,数据结构不一致
`UIFlowEffect` 用 `Array[ControlGroup]`、其余三个用扁平 `Array[Control]`;特效是场景里的 4 个全局节点,
`MyHUD` 只是转发器。该设计在**多玩家/分屏/飞船重生**时必然崩;`UIRotationEffect` 只在 setup 时算一次
`rotation_degrees`,控件移动/屏幕尺寸变化后失效。

### 4.3 玩法模块直接"造 UI"
`module_player_aim`(瞄准)spawn 目标框+血条;`module_booster` 直接注册能量条;`laser_gun_hud_system`
注册准星。违反"HUD 职责固定"——玩法模块应暴露状态(信号/Stat),由专门 UI 控制器构建视图。
目标框+血条+飘字这簇应抽成 `TargetReticle` 组件统一管生命周期。

### 4.4 轮询 vs 信号不一致
`panel_speed` 每帧调 `player.get_speed_string()`(应改 FloatStat);`shield_ui_container` 每帧 lerp;
`EffectManager` 手工缓存 bool。项目明明有 `BoolStat/IntStat/FloatStat` 约定却没用上。

### 4.5 继承体系混乱
`crosshair_1` / `crosshair_2` / `hp_bar_target` 根是 `Node`(内部塞 NinePatchRect);
`crosshair_3` / `crosshair_4` / `dead_zone_indicator` 根是 `Node2D`。"准星"同类东西应统一继承
(Control 或 Node2D),才能统一用锚点/容器布局。

### 4.6 HUD 生命周期未绑定玩家
模块在各自 `_ready` 里注册 UI;玩家死亡/重生时 UI 不会随玩家清理重建,累积重复注册。

## 5. 目标架构核心原则

- **一套注册契约**:`register_hud(element) -> HudElement`,元素用 export enum 自声明归属
  static / far / group;删掉 4 个并行方法。
- **特效 = 纯函数 + 单写者**:`HudEffect.compute_offset(ctx) -> Vector2`,由 `HUDGroup` 的
  `EffectComposer` 汇总后一次性赋值 `position`;Shake 随机游走、Flow/Shake 打架自然消失。
- **生命周期自管**:`HUDGroup` 在 `tree_exited` 时向 manager 反注册;boost 状态直接订阅
  `SignalBus.on_player_boost` 或读 `BoolStat`——删掉 `EffectManager` 与 `get_parent()` 鸭子类型。
- **统一元件基类 `HudElement`**:`bind(ctx)` + 虚方法 `set_target_pos(Vector2)`;
  `crosshair_2/4` 不再 `.call()` + Dictionary(类型安全)。
- **Stat 桥接**:Booster/Heat/Shield/Speed 暴露 `FloatStat`/`IntStat`,UI 元件 `bind(stat)` 订阅;
  `HeatManager` 拆成 `HeatComponent`(逻辑)+ `HeatBarUI`(表现);`SpeedPanel` 停止轮询。
- **伤害飘字世界坐标化**:总线改传 `on_damage_dealt(amount, world_pos)`,由飘字池统一 unproject。
- **投影是服务,不是会动的父节点**(远期):`HUDFarManager` 原地不动,提供 `project(p3d)` 帮助方法。
- **玩法模块不造 UI**:只暴露信号/Stat,专门的 UI 控制器构建视图。
- **HUD 随玩家生命周期**:`create_player_hud(player)`,重生时整体重建,杜绝重复注册。
- **继承统一**:准星/血条统一继承 Control 或 Node2D;清理 `crosshair_1/2` 的 `Node` 根。
- **`UIManager` 定位**:明确为"菜单/暂停/转场"层,或并入 `HUDManager` 作子层——现在留着让人困惑。
