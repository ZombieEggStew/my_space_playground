## 2. 目标架构

### 2.1 核心原则:模块 = 能力 + 该能力 UI 的所有者

> **装模块 → 获得能力(含其 HUD);卸模块 → 能力连同 UI 一起消失,无泄漏、无残留。**

- `HUDManager` 只是**渲染层注册中心**:决定元素挂 static/far/group 哪一层 + 统一特效合成。
- 能力模块负责自己能力的 UI **组装与生命周期**("UI 控制器"从全局外置 → 模块内嵌 `xxx_compat`)。
- 跨模块**状态**走通信层(§2.2);模块内部(父↔子)走树内直连。

**判别规则(节点归属依据)**:
- **玩家固有属性**(不依附任何玩法模块就存在):血量、速度、buff 状态 → **module_hud** 显示,Stat 绑定。
- **模块能力相关**(只有装了模块才存在):目标(radar)、能量(booster)、热量(laser)、护盾(shield)、
  瞄准/预测准星(aim/predict)→ **各模块自持**。
- 数值面板(Stat 驱动)→ 可集中 module_hud;动态元件(每帧位置/几何由玩法驱动)→ 留在玩法模块。

### 2.2 三级通信模型

| 级别 | 载体 | 管什么 | 判定规则 |
|---|---|---|---|
| ① 模块内部 | 树内直连信号 | `xxx_compat` ↔ 玩法逻辑、父↔子 | 收发双方在同一模块树内 |
| ② 飞船级 | `ShipBus`(船上节点,`class_name ShipBus`) | 同船兄弟模块间的输入/状态(aim→predict/missile 等) | 收发双方是同一艘船的兄弟模块 |
| ③ 世界级 | 全局 `SignalBus`(autoload) | 目标 spawn/died、伤害、玩家注册等"世界实体"事件 | 不依附任何一艘船的事件 |

纪律(两级总线通用):**只声明信号,零逻辑零状态**;"当前值"存模块/Stat,bus 只发"变化"脉冲。

**现有 SignalBus 信号归类草案**(迁移视图,雷达机制定稿后可微调):

| 信号 | 归到 |
|---|---|
| `on_player_registered` / `on_lockable_target_spawned` / `on_lockable_target_died` / `on_damage_dealt` | ③ 世界级 |
| `on_player_try_lock` / `on_player_boost_input` / `on_toggle_engine` / `on_toggle_track_mouse` / `on_player_look_backward` / `on_player_look_around` / `on_player_try_use_item_1` / `on_player_boost` / `on_player_shoot` / `on_player_lock_target` | ② 飞船级 ShipBus |
| `on_target_hovered` / `on_target_unhovered` | ① 移除,aim 树内直连 |

### 2.3 命名约定

- 跨模块边界的内容统一 `xxx_compat`(如 aim 的 UI 子模块 → `aim_compat`;radar 的 UI → `radar_compat`)。
- `ShipBus` 为飞船级总线节点;全局 `SignalBus` 只留世界级信号。

## 4. 待讨论 / 待定项

1. **雷达机制(核心待定)**:雷达发布什么、怎么发布——目标"生命周期事件"走③世界级还是雷达在②重发
   ("雷达 = 船的窗口":订阅③ → 维护列表 → 在②发 `on_target_found`,支持范围/阵营过滤);目标血条
   挂雷达后,per-target 的 spawn/回收/数据(血量)怎么管理;目标选择框是否随雷达。
2. **aim 无 radar 时降级策略**:无目标来源时,是 `Log.log_missing_component` + 禁用相关功能(推荐),
   还是 `queue_free` 整个 aim 模块。
3. **module_hud 与 `module_basic_info_ui` 的关系**:改名,还是做成真正的"玩家状态显示模块"。
4. **aim_compat 职责边界**:拥有哪些 2D 节点(crosshair_2? 目标选择框是否被雷达拿走)、与玩法部分
   的接口(信号/方法)、卸载清理路径。
5. **卸载 API**:`ModulesManager` 目前只有 `install_*`,需补 `uninstall_module`(queue_free + 清类型槽),
   且 GROUP 元素(reparent 到 hud_container 的容器)不会随模块释放,需要卸载清理方案。

```powershell
& "D:\.godot\Godot_v4.7.2-stable_win64.exe" --headless --path "D:\AGodotProjects\test-1" --quit-after 15
```
