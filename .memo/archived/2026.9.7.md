## 2. 已修复详情

### 2.1 Bug 1 — 多个特效互相抢占 `position`

**现象/原因**:`UIFlowEffect`(视差)、`UIBoostOffsetEffect`(加速扩散)、`UIBoostShakeEffect`(加速抖动)
直接写**同一组控件**的 `position`,互相拉扯且覆盖作者摆好的布局;其中 `UIBoostShakeEffect` 还是
`position += random` 的**随机游走**,加速时会越抖越偏。

**修复方案**:特效不再直接写 `position`,各自只写 `meta` 里的独立 offset 通道,
由 `HUDManager` 每帧统一合成 `position = 基准位置 + flow + shake`。

| 文件 | 改动 |
|---|---|
| `scripts/Manager/HUD_manager.gd` | 新增 `_dynamic_groups` 追踪;`register_hud_group` 时捕获 `hud_base_pos` 并初始化 offset 通道;`_process` 统一合成 |
| `scripts/ui/ui_float_effect.gd` | 视差只写 `hud_flow_offset` 通道;改用 Dictionary + `is_instance_valid` 防护 |
| `scripts/ui/ui_boost_shake_effect.gd` | 抖动只写 `hud_shake_offset` 通道;随机游走改为平滑 lerp;加 `is_instance_valid` 防护 |

### 2.2 Bug 2 — 远 HUD 坐标系错位

**现象/原因**:`hud_far_manager` 每帧把自己 `position` 设为机头投影 `nose_pos_2d`(整个图层跟随机头),
而 `crosshair_3` 却用**视口全局坐标**(`mouse_pos`/`nose_pos_2d`)设自己的**局部** position,
实际渲染在 `机头 + 鼠标` 处(双重偏移,几乎必偏出屏幕)。`dead_zone_indicator`/热量条是刻意设计成
"机头局部坐标",本身正常。

**修复方案**:保留"远 HUD 图层跟随机头"的现有设计,只修正 `crosshair_3` 的坐标换算,
并把瞄准消费方同步换算回视口坐标。

| 文件 | 改动 |
|---|---|
| `scripts/hud/crosshair_3.gd` | `set_target_pos` / `reset` 改为 `position = 视口坐标 - hud.position`(转机头局部) |
| `scripts/modules/module_component/laser_gun_hud_system.gd` | `get_aim_point_screen_pos()` 返回 `position + hud.position`(转回视口坐标) |
| `scripts/modules/module_laser_gun.gd` | 死代码 `_get_crosshair3_screen_pos()` 顺带同步换算 |

### 2.3 Bug 3 — 特效硬耦合父节点读 boost 状态

**现象/原因**:`ui_boost_offset_effect.gd` / `ui_boost_shake_effect.gd` 通过 `get_parent().is_boosting`
读加速状态,一旦特效节点被重挂载就静默失效;`EffectManager` 整个类只为缓存这一个 bool 而存在。

**修复方案**:两个特效改为 `_ready()` 里直接 `SignalBus.on_player_boost.connect(_on_player_boost)`
自存 `_is_boosting`;删除 `EffectManager`(文件 + 场景引用一并移除)。

### 2.4 Bug 4 — 目标 UI 泄漏风险

**现象/原因**:`module_player_aim` 给每个可锁定目标 spawn 目标选择框 + `hp_bar_target`,靠
`_process` 里 `is_instance_valid(_target)` 自毁;但离屏时 `set_process(false)`,目标在离屏时死亡则
`_process` 不再运行 → 节点永不释放,泄漏。另 `locked_target`/`hovered_target` 目标死亡后会悬挂。

**修复方案**:目标 UI 在 `setup()` 里连 `target.tree_exited → queue_free`(自毁不依赖 `_process`);
`module_player_aim` 监听 `on_lockable_target_died` 清悬挂引用,相关函数加 `is_instance_valid` 防护。

### 2.5 场景加载系统:集中注册表 → `@export PackedScene`(✅ 已迁移)

- 原 `Scenes`(`my_scenes.gd`)集中 preload 注册表已移除(autoload 已删,文件已删)。
- 现约定:需要实例化场景的节点用 `@export var xxx: PackedScene` 在编辑器里绑定。
- 优点:重命名/移动场景由 Godot 按 `uid://` 自动维护引用。
- 残留:`buff_base.gd:24` 的 `preload("res://icon.svg")` 是图标兜底,保留。

## 3. 已完成的结构性问题修复

### 3.1 注册 API 四套并行 → 一套(§4.1,✅ P1)

`register_hud_group / register_hud_static / register_hud_far / register_hud_far_node` 四套并行 API
收敛为 `HUDManager.register_hud(element) -> HudHandle`:
- element 可为 PackedScene(自动实例化)或已有 Node;归属由元素 `@export hud_slot: HudElement.Slot`
  (STATIC/FAR/GROUP)自声明,未声明默认 GROUP。
- `MyHUD` → `HudHandle`(RefCounted 句柄,`.node` 取回节点,GROUP 链式特效)。
- 元素归属声明:`HUDFarBase`(gun_reticle/dead_zone_indicator)→FAR;target_selector/lock_reticle/
  lead_indicator/hp_bar_target→STATIC;heat 的 `laser_gun_heat` 挂 `HUDFarAnchor`→FAR;三个模块容器→默认 GROUP。

**crosshair 类型化**:新增 `HudElement` 元件基类(Node2D,含枚举 `Slot` + 虚方法 `set_target_pos`/`reset`);
`HUDFarBase`/`lead_indicator` 并入。全部准星消费方改为具体 class_name 静态调用
(`HUD_LockReticle`/`HUD_TargetSelector`/`HUD_TargetHPBar`/`HUD_LeadIndicator`/`HUD_DeadZoneIndicator`),
`.call()`/Dictionary 鸭子类型清零。
注意:GDScript 禁止子类重声明继承成员,故 `hud_slot` 不放在基类,各元素脚本自声明。

### 3.2 Stat 桥接(§4.4,✅ P2)

- `PlayerShip` 新增 `speed_stat`/`forward_speed_stat`(FloatStat,`_physics_process` 单写者),
  `panel_speed` 订阅 `value_changed`,删除 `_process` 轮询与 `get_speed_string`/`get_speed_magnitude`。
- `module_shield` 的 setter 直调 → `shield_stat: FloatStat`,`shield_ui_container` `bind(stat)` 订阅。
- `HeatManager` 新增 `heat_stat: FloatStat`(单写者),血条经 `value_changed` 订阅 tween 刷新。
- `EffectManager` 已在 Bug 3 删除。

### 3.3 目标 UI 组件(§4.3,✅ P3 — ⚠️ 方案随后被取代)

新增 `TargetReticle`(一个目标 = 一个组件,持有选择框+目标血条,统一连信号/自毁)与
`TargetReticleController`(挂 HUD_Manager 下,监听 `SignalBus.on_lockable_target_spawned/died` 按目标
spawn/回收);`module_player_aim` 删掉造 UI 代码与雷达依赖,悬停改经
`SignalBus.on_target_hovered/on_target_unhovered` 转发。

> ⚠️ **此方案被新架构方向取代**(2026-09-07 讨论):目标 UI 归属将改为模块自持
> (目标血条归雷达、悬停改树内直连、controller 撤销或内嵌为 xxx_compat),详见 `.memo/.CURRENT.md`。

## 4. 旧目标架构(已被新方向取代)

### 4.1 旧目标架构核心原则(§5,部分已落地)

- 一套注册契约 `register_hud(element) -> HudElement` —— ✅ 已落地(见 §3.1)。
- 特效 = 纯函数 + 单写者(EffectComposer)—— 未做,被新方向替代或顺延。
- 生命周期自管(HUDGroup tree_exited 反注册)—— 未做,并入新方向"模块自持 UI"。
- 统一元件基类 `HudElement`:bind(ctx) + set_target_pos —— 前半 ✅(基类 + 虚方法),`bind(ctx)` 未做。
- Stat 桥接 —— ✅ 已落地(见 §3.2)。
- 伤害飘字世界坐标化(on_damage_dealt 改传 world_pos)—— 未做。
- 投影是服务(HUDFarManager 原地不动,提供 project())—— 未做(远期)。
- 玩法模块不造 UI(专门 UI 控制器构建视图)—— ⚠️ **被新方向修正**:玩法模块改为"能力所有者,
  自持并组装自己能力的 UI",UI 控制器从全局外置改为模块内嵌 xxx_compat。
- HUD 随玩家生命周期(create_player_hud)—— 被新方向取代(HUD 只是渲染层,模块 UI 随模块生命周期)。
- 继承统一(准星/血条统一 Control 或 Node2D)—— 未做(纯整理)。
- UIManager 定位 —— 未做(纯整理)。
